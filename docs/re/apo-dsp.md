## 0. TL;DR for the re-implementation

1. **The DSP math is the same in both builds.** All 3,277 float-looking 32-byte chunks of W7 `.rdata/.data` were compared with W10, and every float constant in W7 also exists in W10. The two values that differ are not DSP data. The effect chain tables, the module factory IDs 0–55, the process gates and the parameter ranges are identical **[C]**. W10 only adds capture-side modules (ASRC, fixed-rate SRC, AEC reference, silence-on-failure, data-dump). The keys new in W10 are read only by AEC/ASRC/FixedSr/MicBeamPlus/PitchShift/VoiceFX **[C]**.
   ⇒ The "Win7 sounds better" difference does **not** come from different effect algorithms in the APO. The likely causes are elsewhere:
   * the OS/INF path: Win7 loads LFX+GFX, so the GFX chain is profile 101, which *includes* SpeakerEQ. Win8.1+ (the `.6.3` INF section) adds SFX/MFX, so the MFX chain is profile 102, which has *no* SpeakerEQ **[C chain contents / I that this is audible]**;
   * the sample rate. Every playback effect bypasses itself above 48 kHz unless the hidden key `{DBD7BD1B-AF04-4960-A346-14E5B58222C2},0` = TRUE, and that key is never set by the INF **[C]**;
   * the kernel driver or format path (another agent's topic).
2. The internal format is **32-bit float, de-interleaved (planar) buffers, fixed blocks**: 448 frames @44.1 kHz, 480 @48 kHz, fs/100 otherwise **[C]**.
3. Render chain for the E1 (stereo speakers or headphones, endpoint form factor Speakers or Headphones), in order **[C]**:
   `BandSplit → CMSS3D(mode 1){Surround + Smart Volume + Dialog Plus} → Reverb(mode 1) → THX Crystalizer → GraphicEQ(10-band) → BassMgmt(SBX Bass) → [SpeakerEQ, GFX/Win7 only] → BandCombine → Calibrator → THX Limiter`.
4. Each block is described below with enough detail to re-implement it: biquad sign convention, crossovers, HRTF FIR sizes, Crystalizer tables, EQ design, AGC weighting, and the limiter.

### 1.2 Initialize (0x18001d0f0) [C]
* Accepts `APOInitSystemEffects` (cbDataSize ≥ 0x38) and `APOInitSystemEffects2` (≥ 0x58, requires InitializeForDiscoveryOnly == FALSE). AudioProcessingMode must be DEFAULT (`{C18E2F7E-933D-4965-B7D1-1EEF228D2AF3}`) or the second GUID at 0x18014f7d0 (RAW/communications [I]).
* It keeps the endpoint property store (`pAPOEndpointProperties`, +0xb8) and the FX property store (`pAPOSystemEffectsProperties`, +0xc0). It creates an `IMMDeviceEnumerator` (CoCreateInstance 0x18014f870) to get notifications (IMMNotificationClient) when properties change.
* Chain selection: FUN_18001c9e0 → FUN_18001bad0 → FUN_18001a3f0 (see §3).

### 1.3 Formats, block size, latency [C]
* **IsInputFormatSupported** accepts only 32-bit float: `wFormatTag==3`, or EXTENSIBLE with the float sub-format and `wBitsPerSample==32` (FUN_18001e020). Compressed formats (`0x92` AC3-SPDIF, or EXTENSIBLE with the IEC61937 sub-format at 0x180152ec8) are recognised by FUN_18001e0a0 and passed through.
* **APOProcess** works on **interleaved float32** from the engine. A "start module" de-interleaves it into planar float buffers (up to 8 channels × 2 sets of pointers), the chain processes them, and an "end module" re-interleaves. A large engine buffer is split into chunks of at most `blockFrames` (+0x124 at run time).
* **Block size** set in LockForProcess (0x18001e8e0): 11025→128, 22050→224, **44100→448**, 88200→896 (W7 only; W10 removed this case so 88.2 kHz uses fs/100 = 882), otherwise **fs/100** (48000→480, 96000→960, 192000→1920). If the engine's own period does not divide this, the start module adds internal buffering (FUN via vtable +0x20) **[C]**.
* **Startup behaviour**: a latency/"prime" value comes from `{DD00ADB4-CC3B-45DA-B49D-DE39F7416780},0` (ms) → +0x130. For the first +0x130 frames the output is a **linear crossfade from dry to wet**: `out = (1-k)·dry + k·wet`, `k = n/N`. A second key, `{54889EB3-F0FA-48D1-84E9-38238C0C5AD2},0` (ms), zero-fills the first +0x140 frames **[C]**.
* **GetLatency** = `+0x130·10⁷/fs` + Σ module latencies (vtable +0x50 of each module) **[C]**.
* Default endpoint formats from the INF: OEMFormat = 2ch/44100/24-bit-in-24 PCM; OEMFormat_FLOAT = 2ch/44100/float32 **[C]**. The live system shows the same values **[C]**.

### 1.4 Device authentication (licensing gate) [C]
FUN_180063960 parses the device-interface path (`…usb#vid_041e&pid_323b…`, type 'B' = USB) and builds a nonce from GetLocalTime + 4 × QueryPerformanceCounter. It opens the device and sends **IOCTL_KS_PROPERTY (0x2F0003)** with property set **`{E8E7B1C0-EB43-4AA5-98EE-7F5DB42D902F}`**, Id 0, Flags 0x200, and a 0x30-byte output buffer (FUN_1800632b0). The reply is decrypted with an AES-like block routine (FUN_1800a4a50; round keys at 0x180169bf0) and must echo the nonce. If it does, VID/PID map to an internal device id (FUN_1800641f0): **PID 0x323B or 0x323E → 0x43 (67)**, 0x323D → 0x44, …. Without a valid reply the device id is 0, and the default/passthrough profile is chosen.
⇒ Our own APO does not need any of this. Note that Creative's APO **cannot work on top of a non-Creative kernel driver**.

## 2. Parameter plumbing

### 2.1 Where parameters live [C]
* All live effect parameters are **PROPVARIANTs in the endpoint's FX property store**: `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\MMDevices\Audio\Render\{endpoint}\FxProperties`, read via `pAPOSystemEffectsProperties->GetValue` (vtable +0x28). Each EfxMod builds a small PROPERTYKEY list in its init (vtable slot 3), reads it, and stores "pending" values. The `Apply` method (slot 9/13) copies pending → current and calls the engine setters. Changes made by the control panel arrive through the property-store/notification path (IMMNotificationClient::OnPropertyValueChanged) **[I for the exact trigger]**.
* INF defaults for E1 (`[SysFx1600.AddReg]` / `.6.3`): Surround on, Immersion 0.4, Crystalizer on, level 0.65, pre-attenuation 1.0, SpeakerMode 2 (headphone), HeadphoneOverride TRUE, plus the Scout set. Identical in W7 and W10 INFs **[C]**.
* `C:\ProgramData\cfSB1600.ini` (and `\Program Files\...\cfSB1600.ini` in the package) is an *obfuscated* settings-override file (pointed to by PKEYs `{BB282A80…},0` / `{872572B3…},0` / `{872572B4…},0`). **Obfuscation: `plain[i] = cipher[i] XOR cipher[i-1]`** (byte 0 is a marker). The same scheme applies to `ksusbaud.ini`, `ksusbchimp.ini` and `CfSB*.ini` **[C]**. Decoded, it holds control-panel defaults: CMSS on, Crystalizer on, speaker mode 2 = headphone, "THX Master Features=47 (0x2F), FeaturesVIP=149" **[C]**. `CfSB1600.ini` is byte-identical in W7 and W10 **[C]**.
* The `.hda` files (`C:\Windows\KSUSB*.hda`, package `*.hda`) are **PKCS#7 security catalogs** (renamed .cat files), not DSP presets **[C]**.
* `C:\Users\Public\Documents\Creative\KsMalc\VID_041E&PID_323B_Playback.xml` holds the control panel's GraphicEQ presets (FeatureId 0x10000010, ParamId 1 = preamp, 2..11 = bands, dB) **[C]**. The control-panel profiles (`Profile\USB_VID_041E_PID_323B\*.xml`) use `surround level`, `crystalizer level`, `bass level / cross_freq`, `svm level / mode`, `dlgplus level`, `graphic_eq preamp / band0..9`, all floats 0..1 except EQ (dB) and cross_freq (Hz) **[C]**.

## 4. Common DSP conventions [C]

* **Biquad (FUN_1800a0150)**, Direct Form I, coefficient order `c[0..4] = {a1, a2, b0, b1, b2}`:
  `y = b0·x + b1·x1 + b2·x2 + a1·y1 + a2·y2` (**feedback ADDED**, so `a1,a2` are the negated textbook values). State is `{x1,x2,y1,y2}`. An anti-denormal constant `1e-10` is added to each input sample and each output (DAT_18015b798). The loop is unrolled ×4.
* **1st-order section (FUN_1800a1eb0)**: `c = {a1, b0, b1}` with the same sign convention.
* **Biquad with coefficient interpolation** (FUN_1800a04c0 / FUN_1800a0460 / FUN_1800a03f0): coefficients are linearly ramped per sample during transitions. GraphicEQ, Bass and Crystalizer use it so changes are click-free.
* **Gain helpers**: FUN_18009ff70 (out = in·g), FUN_1800a07d0 (out = Σ wᵢ·inᵢ, N-input mixer), FUN_18009f390 (circular delay line), FUN_18009f490 (delay-line init).
* **dB→linear**: FUN_18009f530(x) = 10^(0.05·x). **Time constant → one-pole coefficient**: FUN_18009f4c0(ms) = 1 − exp(…) (0 → 1.0). `pow` / `exp` are CRT helpers (FUN_1800b4e70 = pow, FUN_1800b7a30 = exp, FUN_1800b6dc0/FUN_1800b4350 = sin/cos, FUN_1800b72f0 = tan) [I for exact identity of the CRT helpers].
* **Rate gate** (all THX playback modules): process only if `44100 ≤ fs ≤ 192000` **and** (`fs ≤ 48000` **or** the `{DBD7BD1B…}` flag is set). Otherwise the module just forwards to the next one (bypass). Gate flag offsets: CMSS3D +0x14c, THXCrystalizer +0xf8, BassMgmt +0x138, Calibrator +0x108, THXLimiter +0xe8, SpeakerEQ +0x40538, MatrixEncoder +0x1f8. Same in both builds [C].
  ⇒ **E1 at 96/192 kHz with the stock INF: all SBX effects are bypassed** [C code / I that the flag is unset at run time, since the INF/registry never set it].
* **Hi-res mode** (flag set): **BandSplit** (CHspBandSplitState<float,4,4>, FUN_18007f7f0) runs only when fs > 48 kHz. It decimates by `fs/48000` into a 48 kHz base band (the effects then run at 48 kHz) and keeps the upper bands delayed. **BandCombine** reconstructs. CMSS3D clamps its internal rate to 48000 and stores `fs/48000 − 1` [C].
* **Channel layouts**: an internal "speaker config" index is derived from the WAVEFORMATEXTENSIBLE channel mask: 0x3→1 (stereo), 0x7→3, 0xB→2, 0xF→4, 0x33→6, 0x3B→7, 0x3F/0xFF/0x60F→9 (5.1), 0x107→5, 0x13F/0x70F→12 (7.1), 0x63F→14; speakerMode=1 forces 1; headphone override or speakerMode=2 forces **0 (headphones)** [C]. Per-config capability bit tables are at 0x180169aa0 [C].

## 5. Effects — algorithms

### 5.1 CMSS3D EfxMod = SBX Pro Studio "Surround" + "Smart Volume" + "Dialog Plus"
Module: init 0x180053110, apply 0x180053e30, process 0x180052840 (W10: process 0x18005f4f0). Per block of `+0x5c` frames the module runs three engines in this order [C]:

1. **Engine A, Surround** (object +0x158; init FUN_18008a7b0, process FUN_18008aa50, setter FUN_18008ac80 p0..5: p0 enable[0,1], p1 bypass-flag[0,1], p2 immersion[0,1], p3 feedback from engine B, p4 [1,14] output config, p5 [0,14] input config).

3. **Engine C** (object +0x2c340; init FUN_18008d6a0, process FUN_18008d710, setter FUN_18008dc30 p0..3) [I: final up/down-mix and output-gain stage].

### 5.2 THX Crystalizer (EfxMod init 0x180054dd0, process 0x180054a40, apply 0x180055520; core init FUN_18008f340, process FUN_18008f500, setter FUN_18008f910) [C unless noted]
* Params: p0 enable ∈ [0,1], p1 **level** ∈ [0,1], p2 **pre-attenuation** ∈ [0.01, 1] (linear gain applied to the input). Defaults 1 / 0.65 / 1.0.
* Works in **frames of 32 samples** (`uVar14 = 32·n`); parameter smoothing over 16 frames; the coefficient slew limit is 1.19e-6.
* **Analysis** (FUN_18008de30): mono sum (L+R scaled; ×0.55/0.75 depending on whether a centre feed exists). It is split by two per-rate biquads:
  * T1 (0x180166c70): LF band, +6 dB below ~500 Hz, notch ~2.1 kHz, −14 dB above. 48 k: `{1.88129497, −0.888609052, 0.192152217, −0.369676381, 0.192152217}`;

  Rate index: 22050→0, 24000→1, 32000→2, 44100→3 (default), 48000→4.
  Per frame it computes |LF| sum, |HF| sum and peak.
* **Detector** (FUN_18008e090): the peak envelope has attack 0.01 / release 0.001 (per frame), floor 0.03. It normalises the band energies, maps them through a piecewise-linear dB-like curve (FUN_18008e9b0: knots at 0.1, 1.9, 20, 131), and keeps a 5-frame peak memory with decay 0.975. The excess over threshold (param 14) times sensitivity (param 13), capped at 0.5, gives the boost amounts for LF (+0x88) and HF (+0x8c), each with its own smoothing (params 11/12).
* **Level mapping**: `x = (L ≤ 0.5) ? 0.8·L : 0.4 + 1.2·(L−0.5)`; segment 1 = x∈[0,0.38], 2 = (0.38,0.75], 3 = (0.75,1]. Linear interpolation across 4 rows of an 11-float table at 0x180166df0:

  | row | gain | a(rate) | b(rate) | LF amt | HF amt | LF smooth | HF smooth | sens | thr | LF dB | HF dB |
  |---|---|---|---|---|---|---|---|---|---|---|---|
  | 0 | 1.0417 | −0.9508 | 0.7203 | 0 | 0 | 0.1105 | 0.3324 | 1.2098 | 0.45 | 0 | 0 |
  | 1 | 1.10 | −0.9687 | 0.7045 | 0.1522 | 0.6087 | 0.0496 | 0.1823 | 0.9262 | 0.45 | 3.333 | 2.800 |
  | 2 | 1.10 | −0.9777 | 0.6525 | 0.2609 | 0.8696 | 0.0406 | 0.0741 | 0.7986 | 0.50 | 4.133 | 3.600 |
  | 3 | 1.00 | −0.9823 | 0.6336 | 0.3044 | 1.1739 | 0.0246 | 0.0301 | 0.7986 | 0.20 | 5.200 | 5.466 |

  Columns 1–2 actually come from per-rate tables 0x180166d50 / 0x180166da0 (5 rates × 4 rows) [C].
* **Static shaping filter** (FUN_18008e6d0): two first-order shelves with gains `LF dB` / `HF dB` (10^(dB/20)), built by the bilinear transform (tan prewarp), multiplied into one biquad (`+0x80..0x84`, scaled by row gain × pre-attenuation).
* **Dynamic section** (FUN_18008e510): a first-order "tilt" whose pole/zero move with the detector boosts: `g = ((amt·4·boost + 1)·k + 1)·0.5` for LF and HF. Coefficients are recomputed per frame and slewed.
* **Signal path per channel**: `y = Biquad_static( FirstOrder_dynamic( x ) )`, then the output gain. Front L/R, centre and surrounds all go through the same path; LFE is only gain-scaled.
* In short, the Crystalizer is a **transient-driven dynamic shelving EQ (LF+HF "expander")** plus a level-dependent static loudness tilt, done at 32-sample frame rate.

### 5.3 GraphicEQ ("THX EQ", EfxMod 0x1800560a0 init; engine init FUN_180084e00, process FUN_180085230, setter FUN_180085680) [C unless noted]
* **10 bands**, default centres **31.25, 62.5, 125, 250, 500, 1k, 2k, 4k, 8k, 16k Hz** (0x180166950). Default bandwidths 22.09…11312 Hz = 0.7071·fc (**one octave**, Q ≈ 1.414).

The peaking form is the all-pass/Regalia-Mitra constant-Q design: `G=10^(g/20)`, `t = tan(BW/2)/√G` (boost/cut symmetric), `k=(t−1)/(t+1)`, `a2=k`, `b0=(1+G)/2 − (1−G)/2·k`, `b2=(1−G)/2 − (1+G)/2·k`, `a1/b1` from `−cos ω0·(1−k)`. * The 10 biquads are cascaded per channel. Coefficient changes **cross-fade over 11 blocks** (FUN_1800a04c0). A preamp gain is applied. An optional **auto-normalisation** (`+0x964`) uses the product of the sections' Nyquist gains (FUN_180085bf0) [C].

## 7. Clean-room re-implementation spec (for our C APO)

Processing graph per buffer (float32 planar, block = fs/100, or 448 at 44.1 k so it divides by 32), at **any rate up to 192 kHz natively**. The original's 48 kHz cap was a CPU/licensing limit, not a quality feature.

```
in (L,R) ─► [Pre-atten] ─► Surround (upmix → rear all-pass decorrelate → HRTF binaural if headphones /
            crosstalk virtualizer if speakers; immersion = wet/dry 0..0.6)
         ─► Smart Volume (BS.1770-weighted, 64-smp frames, 96-smp look-ahead, level table −52 dB / 0..50 dB)
         ─► Dialog Plus (mid/side: +a dB centre, b dB sides, +c dB presence; level table above)
         ─► Crystalizer (32-smp frame transient detector on LF/HF bands → dynamic 1st-order tilt + static
            shelf pair; level table above)
         ─► 10-band EQ (low-shelf 31.25 Hz, peaking ×8 octave Q≈1.41, high-shelf 16 kHz; ±12 dB UI,
            preamp ±12 dB, 11-block coefficient cross-fade)
         ─► Bass (Butterworth/LR crossover at 80 Hz default (10–1000 Hz); low-band enhancer 0.875·fc)
         ─► (optional) headphone/speaker tuning EQ
         ─► Look-ahead limiter (≈1.5 ms, 250 ms release, sub-block peak detect)
         ─► out
```
* Use double precision for biquad state at high sample rates (≥96 kHz with fc = 31 Hz), or use TPT/SVF structures. The original's float DF-I with a 1e-10 offset will lose low-frequency precision [I].
* Smooth every parameter (the original ramps over 11–16 blocks).
* No 48 kHz gate, no device authentication, and no LFX copy stage.
* Expose parameters through the same PKEYs (table §2.2) so the original SBE.exe control panel can still drive the new APO, if desired.

### V.2 Things missed in this subsystem
1. **Re-blocking to 128 frames** (#3). A faithful clone running at 480-frame blocks will have different smoothing and frame-rate constants: every "per block" time constant in the modules (Crystalizer 16 frames, bass `round(fs*0.01/128)`, EQ ramps) assumes the module block, i.e. 128 here.
2. **The LFX/SFX MatrixEncoder is live, not a memcpy** (#2). On Win11 the SFX (`{E9B73398...}`, profile 37) runs MatrixEncoder before the mix, and MFX profile 102 runs after it. What MatrixEncoder does to a stereo stream is not established (UNVERIFIABLE statically without more work). A re-implementation should start by treating it as identity and test against the original.
3. **The GraphicEQ preamp is folded into section 0**, and coefficient changes ramp one section at a time over about 10 ms each (#7).
4. **The GraphicEQ and Reverb have no fs > 48 kHz gate**, so at 96/192 kHz the original still applies the EQ while everything else bypasses.
5. **Live control-panel state on this PC (FxProperties)**: Surround ON at 0.4, Crystalizer ON at 0.65, pre-atten 1.0. Smart Volume `{9AD782D7}` = FALSE with level `{80B0C7BB}` = 0.74, which matches the engine-B default 0.74 and supports the analyst's INFERRED mapping. Dialog Plus `{EA3137F9}` = FALSE, level `{A79717E9}` = 0.5. EQ enable `{9A9D0CB2}` = FALSE, preamp `{DDCF8D90}` = 0.0, bands `{2B88C76D},0..9` = 0. Bass `{F67CF426}` = FALSE, `{0519A199}` = FALSE. SpeakerMode = 2, HeadphoneOverride = TRUE, Scout keys present with Scout0 = FALSE. Two keys written by the control panel are **not read by the APO at all** (absent from the W7 PKEY list): `{3C14ECCC-4A1F-47F7-91DD-BF45AF920A4D},0` = TRUE and `{1A2C8ED7-D5B0-469F-A2E7-7362A4F34691},0` = 9 [C absent; purpose UNVERIFIABLE here, probably for another component].
6. **The FxProperties processing-mode lists** `{D3993A3F-99C2-4402-B5EC-A92A0367664B},5/6` = DEFAULT only, so the RAW/communications branch in Initialize never runs on this endpoint.
7. **The auth reply contains more than the nonce**: a type selector (0/1/2) and device-identity fields that are compared with the interface path. Our own APO does not need any of this, but a clone kernel driver that wants to host *Creative's* APO would have to implement BASICSUPPORT on that set, which is not feasible without the key schedule. Treat the Creative APO as unusable on a non-Creative driver (agrees with 1.4).
8. **Biquad state order** {x2, x1, y2, y1} (#6). This matters only if state is shared or serialised.
